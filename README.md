# 账务明细自动分类汇总

影刀 RPA 实操题：把 16 万行账务明细按 30 个财务科目自动归类，输出《支出拆解表》，并用总额除法核验结果。

> 仓库内为**合成演示数据**：科目名称、平台名称、金额、订单号均已泛化或替换，不对应任何真实商户。

## 结果

| 项目 | 数值 |
|------|------|
| 明细行数 | 160,510 |
| 收入合计 | +10,521.54 |
| 支出合计 | -101,214.00 |
| 汇总净额 | **-90,692.46** |
| 未匹配行数 | 0 |
| 核验 | 30 个科目金额与匹配表完全一致 |

## 方法

针对“业务描述 ≠ 分类名称”的问题，采用分层匹配：

1. **编码精确匹配**：`1000002|技术服务费-基础技术服务费` → O(1) 查表（66.8%）
2. **忽略编码差异**：`1000038|技术服务费-返点积分（退款）` 按 `|` 后文字归入 `1000003|技术服务费-返点积分`
3. **关键词匹配**：`推广平台自动充值`、`先享后付技术服务费` 等 17 条纯文字规则
4. **特殊规则兜底**：平台补贴、营销托管、推广联盟、平台保证金扣除转移、提现
5. **描述缓存**：相同描述只匹配一次，避免 16 万行重复计算

## 影刀集成

```python
import expense_breakdown

result = expense_breakdown.main(匹配名称字典)
# result = {'summary': {分类名: 金额}, 'total': 总金额}
```

影刀侧流程：读取匹配表 → 构建字典 → 调用 Python → 按分类名回写《支出拆解表》 → 总额除法核验。

## 数据说明

`project/作业素材/源文件/demo_account_202512_账务明细.csv` 为合成数据：

- 平台名称、公司名称、邮箱统一改为“平台 / 示例”等通用词
- 业务编码替换为 `1xxxxxx`、`9xxxxxxxxxxx` 形式的假编码
- 金额按比例缩放并加入 ±15% 随机扰动，收入/支出结构保留
- 订单号、流水号重新生成为 19 位数字
- 买家商品标题替换为“买家备注：商品规格说明”

因此仓库可以完整跑通匹配流程，但不含任何真实经营数据。
